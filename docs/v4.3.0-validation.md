# Stage Flux v4.3.0 implementation and validation

Date: 2026-09-23

## Scope

Added Restoration, Battery Drain, Heavy Cargo, Butterfingers, Enemy Blindness,
Enemy Armor, Enemy Vulnerability, Supply Drop, Player Swap and Shared Pain.
Emergency Recall and Shared Recovery were not implemented. Total: 46 events.
All ten additions default to enabled with a 6% independent chance. Existing user
settings are not reset. Global simultaneous-event limits and event modes remain in use.

Only StagePhysicsEvents project files were changed. RoleShuffle and
EliteEnemyVariants sources and optional compatibility API contracts were not changed.
No new hard dependency, client-required RPC, or external-mod HUD information was added.

## Implementation

- `EventModels.cs`: ten additional 64-bit flags, event enumeration, display/chat names.
- `ExtendedEventConfig.cs`: REPOConfig settings and default values.
- `ExtendedEventPolicy.cs`: bounded repair, charge and damage arithmetic.
- `ExtendedEventAdapter.cs`: host-side lifecycle, object filtering, recurring pulses,
  stage-limited supplies, safe pair selection and asynchronous damage propagation.
- `ExtendedEventPatches.cs`: per-call enemy damage scaling, scoped sight-range scaling,
  host-local/remote health-loss observations.
- `StagePhysicsConfig.cs`: registration, logical exclusions and dangerous-combination risks.
- `StagePhysicsEventController.cs`: availability, start/tick/stop and stage cleanup.
- `VanillaSpawnEffectResolver.cs`: reuse existing vanilla-only prefab validation.
- `EventPresentation.cs`: danger colors for new events.
- `StagePhysicsEventsPlugin.cs`, `StagePhysicsEvents.csproj`, `package/manifest.json`: version 4.3.0 and compilation/patch registration.
- `package/README.md`, `package/CHANGELOG.md`: player-facing English/Japanese catalog and settings; English-only changelog.

Heavy Cargo never targets players, enemies or doors. Hierarchical carrier markers
exclude implementation-only objects from the new object/enemy/player paths.
Heavy Cargo and Butterfingers valuable protection require both their own setting and
Targets.Valuables. Their timed leases expire without clearing another mod's leases.

Restoration repairs the gap between current displayed value and displayed full value;
changing the event price alone is not a repairable loss. Battery Drain preserves the
host's exact charge after using vanilla battery-bar synchronization.

Enemy damage is scaled once per Hurt call; existing defenses are not replaced.
Enemy sight fields are scaled only while each Vision coroutine step executes and
restored in a finally block, retaining other mods' base values. Hearing is untouched.

Player Swap requires two living, standing, grounded, empty-handed players. Both
destinations are checked against the NavMesh and collision volume before either
vanilla Spawn call. It does not retake a stage or alter extraction state.

Shared Pain observes actual accepted health loss, excluding initialization, maximum
health changes and health donations. Its generated damage carries vanilla hurtByHeal
through asynchronous client health acknowledgements, preventing recursive sharing.
Bodyguard corrective revival is allowed to take priority. Nonlethal mode caps against
the host's latest HP and enables vanilla saving grace; network-concurrent damage is
not a strict guarantee against death.

Supply items are standard usable items, not internal carriers. Health packs and
trackers/tools are allowed; explosives, weapons, upgrades and custom assets are not.
Generation is staggered, capped across the entire stage and canceled on event/stage
end. Successfully spawned items are deliberately not removed at event end.

## Artwork

Ten dedicated icons were created with the built-in image_gen tool using the imagegen
skill. Source artwork is in `Assets/EventIcons/masters/<Event>.png`; alpha-preserving
512x512 HUD exports are in `Assets/EventIcons/Runtime/<Event>.png`.
Exact prompts and generated source paths are recorded in
`Assets/EventIcons/v4.3.0-generation.json`. The import script is
`tools/import_generated_event_icons.ps1`. No generated images were added to README.

## Remaining in-game verification

No interactive singleplayer or vanilla-client multiplayer session was run here.
Automated checks establish code/assembly consistency, not observed gameplay.

1. Force each new event separately; verify clients without Stage Flux see the same
   health, battery, item, enemy and teleport results.
2. Damage a valuable before and during Value Crash/Surge; confirm Restoration does
   not repair a multiplier-only change and leaves repaired damage after the event.
3. Verify Heavy Cargo ends normally and never affects players or doors; test ordinary
   DroneToOrbItem items and exclusion of RoleShuffle root/child carriers.
4. Test Butterfingers with multiple holders, inventory items, protections on/off and
   Targets.Valuables off.
5. Compare enemy sight at near/far distances and noise response; test Armor and
   Vulnerability with existing elite defenses and newly activated enemies.
6. Confirm Supply Drop items are pickable, persist after the event and stop at the
   configured stage budget, including repeated activations and persistent mode.
7. Test Player Swap with clear floor, narrow doorways, stairs, carried objects,
   tumbling, deaths, disconnections and different player sizes.
8. Test Shared Pain from host and vanilla participant damage, health donations,
   death/revival and simultaneous hits. Confirm no repeated sharing acknowledgements.
9. Check new icons in both HUD orientations and notification names without spaces.
